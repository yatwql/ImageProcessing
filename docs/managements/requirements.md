# 需求文档（Requirements）

> 版本：v0.1

- 项目：retype / PNG 文字替换
- 版本：1.0
- 更新：随代码同步维护

## 1. 背景与问题

运营、设计、行政经常需要复用已有的 PNG/JPG 图片（海报、邀请函、通知、报价单、课程表等），
只改其中几个字（年份、姓名、电话、金额），其余文案与排版必须保持原样。

现有做法的问题：

| 做法 | 问题 |
| --- | --- |
| 重新排版 | 原字体往往找不到，重排后版式全变 |
| 用修图软件逐字擦除重打 | 手动、不可批量、难以保证字号字色一致 |
| 让 AI 整图重绘 | 文字内容与排版不可控，容易改坏其它文字 |

因此需要一个可脚本化、可交互的本地工具：**只改指定文字，其余像素不动**，新文字自动沿用原文字的
字体、字号、字重、字色、字距与位置。

## 2. 目标用户与场景

| 用户 | 场景 | 期望 |
| --- | --- | --- |
| 运营 / 设计 | 一批海报换年份、换价格 | 一次跑完整个目录，规则复用 |
| 行政 / 教师 | 邀请函、通知换姓名与日期 | 有一块一块挑着改的界面，改完立刻看结果 |
| 开发 / 自动化 | 集成到流水线 | 命令行 + JSON 映射表 + 明确的退出码 |

## 3. 范围

### 3.1 范围内

- 输入：本机图片文件（png/jpg/jpeg/bmp/webp/tif），单文件或单个目录（不递归）。
- 文字定位：自动 OCR 定位，或手工指定矩形区域。
- 替换：整行替换、行内部分文字替换。
- 样式沿用：字体、字号、字重、字色、字距、对齐位置。
- 交付渠道：命令行（单图 / 目录批量）、终端交互界面（TUI）。
- 输出：另存为新文件，默认 `data/output/`，绝不覆盖原图。

### 3.2 范围外（非目标）

- 不改整体版式，不支持重新排版、换行重排段落（新文字含 `\n` 时仅做简单多行绘制）。
- 不支持竖排、旋转、弧形文字的旋转适配。
- 不做图像生成式修复；复杂纹理底图上的擦除效果不作为验收项。
- 不提供 GUI 桌面程序与网络服务。

## 4. 功能需求

编号规则：FR-x 为功能需求，NFR-x 为非功能需求，优先级 P0 最高。

### FR-1 文字定位（P0）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-1.1 | 自动识别图中的文字块及其包围盒 | 对样例图（中文正文 + 中文标题 + 数字）识别出主要文字块，`--list` 可打印 |
| FR-1.2 | 支持手工指定区域替换 | `--area x,y,w,h=新文字` 可用，不依赖全图 OCR |
| FR-1.3 | 区域内的原文字可自动获取用于样式匹配 | `--area` 模式下对区域做局部 OCR，取最宽的一块作为原文 |

### FR-2 文字替换（P0）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-2.1 | 整行替换 | 映射表 key 等于整行文字时，该行整体重绘为新文字 |
| FR-2.2 | 行内子串替换 | key 是某行的一部分时，只擦除并重绘这几个字，同行其他文字像素不变 |
| FR-2.3 | 一处 key 命中多处时全部替换 | 同一 key 在多行/多图出现均被替换 |
| FR-2.4 | 未命中要给出反馈 | 打印「未找到待替换文字」，不静默跳过 |
| FR-2.5 | 模糊兜底 | 完全/部分匹配都没有时，相似度 ≥ 0.8 的块按整行替换并提示 |

### FR-3 样式沿用（P0）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-3.1 | 自动匹配字体与字重 | 在候选字体中选出最接近的一款（含常规/粗体/衬线/非衬线区分） |
| FR-3.2 | 字号自动反解 | 与原文字迹高度一致，误差 ≤ 2px |
| FR-3.3 | 字色自动取样 | 与原文字色一致（取笔画核心像素中位数） |
| FR-3.4 | 字距沿用 | 稀疏排布的大标题/逐字加宽的标题也能复现字距 |
| FR-3.5 | 位置沿用 | 垂直居中原字迹，水平按 auto/left/center/right 落位 |
| FR-3.6 | 允许人工覆盖 | `--font / --size / --color / --tracking / --fit-width` 可强制指定 |
| FR-3.7 | 匹配不可靠时必须提示 | 相似度过低时退回默认字体并在 stderr 说明原因 |

### FR-4 命令行渠道（P0）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-4.1 | 单图替换 | `cli.sh 图.png --map "旧=新"` 生成输出文件 |
| FR-4.2 | 目录批量 | `cli.sh data` 遍历目录内所有支持格式，逐张套用同一套规则 |
| FR-4.3 | 映射表文件 | `--map-file x.json`；与 `--map` 可叠加，`--map` 优先 |
| FR-4.4 | 预演模式 | `--dry-run` 打印将发生什么但不写文件 |
| FR-4.5 | 列表模式 | `--list` 输出每张图的文字块、位置与置信度 |
| FR-4.6 | 批量汇总 | 结束时打印成功/失败/无匹配张数与替换总数 |
| FR-4.7 | 明确退出码 | 至少一处成功为 0，全失败为非 0 |

### FR-5 交互渠道（TUI）（P0）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-5.1 | 图片列表 + 文字块列表双栏 | 左右分栏，可 `Tab`/`t` 切换焦点 |
| FR-5.12 | 图片列表带序号 | 可见行前显示 1..9、第 10 项为 0，按对应数字直接跳到该图片 |
| FR-5.2 | 选中块设置新文字 | `Enter` 整行替换、`i` 行内替换 |
| FR-5.3 | 启用/禁用 | `空格` 切换单个块，`a`/`n` 全启用/全禁用 |
| FR-5.4 | 全局映射 | `e` 维护映射表，`m` 把当前块加入映射，其它图片自动生效 |
| FR-5.5 | 映射导出 | `w` 导出 JSON，可被 CLI 的 `--map-file` 直接复用 |
| FR-5.6 | 执行当前/全部 | `r` 替换当前图，`R` 批量替换（需确认） |
| FR-5.7 | 状态可见 | 底部有详情行、消息行、键位提示；执行中显示进度，结束显示输出路径与处数 |
| FR-5.8 | 中文与宽字符正确排版 | 中文不串行、不截断错位，长行有完整内容展示位 |
| FR-5.9 | 记忆与缓存 | 切换图片记住选中块；重复替换同一张图应基本即时完成 |
| FR-5.10 | 帮助 | `?` 显示完整键位与典型流程 |
| FR-5.13 | 目录浏览 | `d` 打开浏览面板：可进入子目录、`Backspace` 回上级、选中其中的图片；隐藏项与非图片文件不列出 |
| FR-5.14 | 默认数据目录 | 未给参数时读 `/data`（不存在则 `data/`），可用 `IMG_P_DATA_DIR` 覆盖 |
| FR-5.11 | 样式选项面板 | `c` 可改字体、字号、字色、对齐、贴合宽度、字距、字体上限，留空即自动，非法输入只提示不崩溃 |

### FR-6 输出与安全（P0）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-6.1 | 默认输出目录 | `data/output/`，可用 `-o/--out-dir`（TUI 用 `o`）覆盖 |
| FR-6.6 | 重名不覆盖 | 目标已存在同名文件时自动追加 `-1`、`-2`…，扩展名不变 |
| FR-6.2 | 不覆盖原图 | 原文件保持不变；输出路径等于原图时拒绝写入并报错 |
| FR-6.3 | 幂等 | 同一张图重复替换结果一致，不产生重影叠加 |
| FR-6.4 | 透明通道 | 带 alpha 的 PNG 在擦除处一并修复 alpha，不留下原字形轮廓 |
| FR-6.5 | 批量确认 | TUI 批量替换前必须二次确认 |
| FR-6.7 | 元数据保留 | 原图的 ICC 色彩配置、EXIF、DPI 在目标格式支持时带到输出上 |
| FR-6.8 | 输出质量可调 | `--quality 1-100`（TUI 样式面板同项）控制 JPEG/WEBP 质量，默认 95 |

### FR-7 写盘日志（P0）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-7.1 | 写盘即记日志 | 只要真实写出一张图（替换结果、`--debug` 调试图），就向 `logs/` 下的日志追加一条记录；`--dry-run` 不记 |
| FR-7.2 | 记录内容完整 | 每条包含发生时间、来源渠道（cli/tui）、源文件名与大小、目标文件名与大小、具体替换（旧文字→新文字、模式、字体、字号、字距、颜色、对齐、匹配度） |
| FR-7.3 | 追加不覆盖 | 日志按天分文件（`image-writes-YYYYMMDD.log`），一行一个 JSON 对象，只追加不改写 |
| FR-7.4 | 目录可配 | 默认仓库根 `logs/`，CLI 可用 `--log-dir`、任意渠道可用环境变量 `IMG_P_LOG_DIR` 覆盖 |
| FR-7.5 | 日志失败不毁结果 | 日志写不进去只提示一句，图片已保存的事实与退出码不受影响 |
| FR-7.6 | 日志可校验 | 记录目标图的尺寸与 sha256，可核对磁盘上的文件是否就是日志里那次写入 |
| FR-7.7 | 自动轮转 | 只保留最近 30 天的日志，更早的按天文件自动清理 |

### FR-8 运行摘要（P1）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |

| FR-8.2 | 预演也留摘要 | `--dry-run` 时摘要里 `dry_run=true`、`saved=false`，便于排查而不写图 |

### FR-10 批量替换的进度与中断（P1）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-10.1 | 进度可见 | 批量替换时每条进度含「当前序号/总数 + 图名」，界面消息行实时更新 |
| FR-10.2 | 可中断 | 批量途中按 Esc 停止，已完成的结果保留，状态行显示「已取消，完成 x/n」 |
| FR-10.3 | 不误停 | 只有 Esc 触发中断；`q` 在其它面板是「返回」，不得导致批量静默中止 |
| FR-10.4 | 单图内也能停 | 中断不只在两张图之间生效：`replace_image(should_stop=)` 每块之前询问，OCR/匹配之后按 Esc 同样能停下 |
| FR-10.5 | 保留已完成 | 中断时已完成的块写入报告，状态行显示「已取消，完成 x/n」，不丢已有结果 |

## 7. 验收方式

```bash
./scripts/setup.sh                                  # 环境
./scripts/cli.sh data/demo --list                        # 识别正常（示例图）
./scripts/cli.sh data/demo --map "2023=2024" --dry-run   # 批量预演
./scripts/cli.sh data/demo --map "2023=2024"             # 批量出图 → data/output/
./scripts/tui.sh                                    # 交互界面可操作
.venv/bin/ruff check --select E,F,B,I --ignore E501 src/
```

人工验收要点：替换后目标文字样式与原文一致、同行其余文字像素不变、原图未被修改、重复执行无重影。
