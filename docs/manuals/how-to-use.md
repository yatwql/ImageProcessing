# 使用手册（how-to-use）

> 版本：v0.4-dev

本文是面向使用者的操作手册。想了解内部实现请看 `docs/managements/technical.md`。

## 1. 它能做什么

把图片里的某几个字换成别的字，其它文字的内容和排版一个像素都不动；新文字自动沿用原文字的
字体、字号、字重、字色、字距和位置，原图不会被覆盖。

```text
改前：年度销售报告 2023          改后：年度财务总结 2024
      本季度总收入为 1,234,567 元       9,876,543（只动数字，同行其它字不变）
      负责人：张三                     负责人：李四
```

两种用法：

| 想过什么 | 用哪个入口 |
| --- | --- |
| 一次处理一个目录 / 写进脚本 / 定时任务 | `./scripts/cli.sh` |
| 想一块一块挑着改、改完马上看结果 | `./scripts/tui.sh` |

## 2. 准备

```bash
./scripts/setup.sh
```

Windows（PowerShell）：

```powershell
.\scripts\setup.ps1          # 需要跑测试时用 .\scripts\setup.ps1 -Dev
```

会创建 `.venv` 并安装 Pillow、numpy、opencv、RapidOCR（离线中英文 OCR）。需要 Python ≥ 3.10，
系统里要有字体；Linux/macOS 走 fontconfig（`fc-list`），Windows 直接读
`C:\Windows\Fonts` 与 `%LOCALAPPDATA%\Microsoft\Windows\Fonts`，中文出问题时见第 8 节。
后面的命令示例用 `./scripts/cli.sh`，Windows 换成 `.\scripts\cli.ps1`（`tui`/`test` 同理）。

配置文件在 `/data/config/retype.json`（模板 `/data/config/retype.example.json`，可用 `IMG_P_CONFIG` 指定），
`setup.sh` 首次会生成一份默认值：

```json
{
  "data_dir": "/data", "out_dir": "/data/output", "log_dir": "/data/logs",
  "align": "auto", "max_fonts": 160, "quality": 95, "fit_width": false
}
```

优先级：命令行/界面里显式设置 > 环境变量 > 配置文件 > 内置默认。改完配置不用重启，下次运行生效。

把待处理的图片放进数据目录：默认是 `/data`（容器里常见；不存在时退回仓库 `data/`），
可用环境变量 `IMG_P_DATA_DIR` 指定；命令行则把路径作为第一个参数。支持的格式：

| 类型 | 格式 |
| --- | --- |
| 输入 | png、jpg/jpeg、bmp、webp、tif/tiff（按扩展名识别，大小写不敏感） |
| 输出 | 默认写 `<原文件名>.png`（无损）；用 `-o 名字.jpg` 可指定 jpg（质量 95，透明底会合成为白底） |

jpg 图片上的压缩噪点对识别影响不大；如果是压缩很狠的图，识别不准时按 `l` 重识别或用 `--area` 手工框。

仓库自带一组示例图（`data/demo/`），可以直接拿来试：

| 图片 | 内容 |
| --- | --- |
| `示例-报告.png` | 标题「年度销售报告2023」+ 一行正文 + 负责人：张三 + 日期：2023-12-31 |
| `示例-通知1.png` | 标题「年度报告 2023」+ 正文 + 电话：400-800-1234 |
| `示例-通知2.png` | 标题「季度总结 2023」+ 正文 + 电话：400-800-5678 |
| `示例-通知3.png` | 标题「项目复盘2023」+ 正文 + 电话：400-800-9999 |

四张图的正文都是「本页内容保持不变，排版一致。」，用来检查替换时其它行是否一个像素都没动。

### Windows 注意事项

- 首次使用**直接跑** `.\scripts\cli.ps1 data --list` 即可：发现没有 `.venv` 或依赖缺失会自动安装
  （提示「首次运行，正在准备环境…」，约 1~2 分钟）；想提前装或离线装用 `.\scripts\setup.ps1 -Dev`。
  设 `IMG_P_NO_AUTO_SETUP=1` 可关掉自动安装，只提示不改环境。
- 脚本文件是 UTF-8 with BOM：Windows PowerShell 5.1 对无 BOM 文件按 ANSI 解码，
  中文提示会变成乱码。若你改过脚本，请保持 BOM（或用 PowerShell 7）。
- 交互界面依赖 `windows-curses`（由 `pyproject.toml` 的平台标记自动安装）。

## 3. 三分钟上手（命令行）

```bash
# 1) 先看图片里有哪些文字块，方便抄 key
./scripts/cli.sh data/demo/示例-报告.png --list
```

输出类似：

```text
== data/demo/示例-报告.png（4 块）
  [0] (64,58) 362x39  score=0.85  年度销售报告2023
  [1] (64,150) 341x24  score=0.88  本页内容保持不变，排版一致。
  [2] (64,210) 152x23  score=0.82  负责人：张三
  [3] (65,270) 207x24  score=0.88  日期：2023-12-31
```

```bash
# 2) 替换：把 key 抄进 --map，可写多条
./scripts/cli.sh data/demo/示例-报告.png \
    --map "年度销售报告2023=年度财务总结2024" \
    --map "负责人：张三=负责人：李四" \
    --map "日期：2023-12-31=日期：2024-01-15"
```

结果写在 `data/output/示例-报告.png`，原图不动。

```bash
# 3) 整个目录一起处理（示例图会一起换掉 2023）
./scripts/cli.sh data/demo --map "2023=2024"

# 4) 先预演，确认会改什么再执行
./scripts/cli.sh data/demo --map "2023=2024" --dry-run
```

## 4. 三分钟上手（交互界面）

界面长这样（宽屏双栏，边框会按真实终端画；标题里的日期是代码最后更新日）：

```text
┌ retype v0.1 (2026-11-18) · 图片文字替换 ────── 2/5 张 ┐
│ ① 图片 2/5        │ ② 识别到的文字 2/6           │
│    ..  上级目录    │ ● 年度销售报告2023           │
│  1 · 示例-报告.png │ ○ 负责人：张三               │
│  2 ✓ 示例-通知1.png│ ○ 日期：2024-01-01           │
├───────────────────┴─────────────────────────────┤
│ 选：年度销售报告2023　→ 年度财务总结2024            │
│ 输出 data/output　已保存 示例-报告.png  [██░░] 35% │
│ ↑↓ 选图  Enter 右栏  r 替换  R 全部  Ctrl-R 刷新  │
└──────────────────────────────────────────────────┘
```

手机会自动切成单栏（宽度 < 60 列）：只显示当前焦点那一栏，`Tab` 来回切换；
宽度 < 44 列时表头只留计数，宽度 < 40 列时键位提示也换成最短的一组。

> 目录里还没有图片也能进界面：看好位置后把图片复制进去，按 `Ctrl-R` 重新扫描即可。

```bash
./scripts/tui.sh
```

界面分左右两栏：左边是图片，右边是这张图识别出来的一行行文字。

```text
 ① 图片 1/5                    ② 识别到的文字 1/6  Enter 整行换  i 只换几个字
 · 示例-报告.png        │  ○ 年度销售报告2023   （还没设置新文字）
                        │  ● 负责人：张三   换为→ 负责人：李四
```

### 4.1 只换一行里的某几个字

1. `↑↓` 选图片 → `Enter` 进右栏（首次会自动识别，等一秒）
2. `↑↓` 选中那行 → 按 `i`
3. `这行「…」里要替换哪几个字:` → 输入 `2023` → 回车
4. `把「2023」换成:` → 输入 `2024` → 回车
5. 按 `r` 执行 → 底部出现 `已保存 …/data/output/示例-报告.png（1 处：…）`

只有这几个字被重画，同行其它文字不变。

### 4.2 整行换掉

选中那行按 `Enter`（输入框会预填原文字，直接打字会整体替换），输入新内容，回车，再按 `r`。
如果没改内容直接回车，会提示「内容和原来一样，没有改动」，不会误替换。

### 4.3 多张图用同一套规则

- 给一个块设好后按 `m`：把「旧→新」加入全局映射，其它图片的同名文字自动生效；
- 再按 `R` 批量替换（会先要求输入 `y` 确认）；
- 按 `w` 可以把映射导出成 JSON，之后命令行也能复用：
  `./scripts/cli.sh data --map-file map.json`。

### 4.4 样式选项（`c`）

自动匹配偶尔不合意时，按 `c` 打开样式选项，`↑↓` 选中、`Enter` 改值，**留空表示自动**：

| 选项 | 填什么 |
| --- | --- |
| 字体文件 | `.ttf/.otf/.ttc` 路径，留空=自动匹配 |
| 字号 | 整数像素，留空=按字迹高度反解 |
| 字色 | `#FF0000` 或 `255,0,0`，留空=取原字色 |
| 对齐 | `auto`/`left`/`center`/`right` |
| 贴合原宽度 | `on`/`off`，等价于命令行的 `--fit-width` |
| 额外字距 | 像素值（可负），留空=自动 |
| 候选字体上限 | 默认 160，数值越小匹配越快 |
| JPEG 质量 | `1`-`100`，留空=默认 95（只影响 jpg/webp 输出） |

改完按 `Esc` 回到主界面，再按 `r` 生效。这些设置只影响本次会话。

## 5. 替换规则

命令行与 TUI 的映射表遵循同一套规则：

| key 与识别到的整行文字 | 行为 |
| --- | --- |
| 完全相同（忽略空格） | 整行替换 |
| 是某行的一部分 | 只替换这几个字，同行其它文字原样保留 |
| 相似度 ≥ 0.8 | 整行替换，并在终端提示“模糊匹配” |

一个 key 命中多处（多行、多张图）时全部替换。比较时忽略空格、忽略零宽字符，全角/半角视为相同
（`２０２３` 与 `2023` 能匹配上）。

```bash
# 整行
--map "负责人：张三=负责人：李四"
# 行内（只动数字）
--map "1,234,567=9,876,543"
# 行内（只动年份，影响所有出现位置）
--map "2023=2024"
```

## 6. 输出

| 用法 | 输出位置 |
| --- | --- |
| TUI | `data/output/<原文件名>.png`，界面里按 `o` 可改 |
| CLI 单图 | `data/output/<原文件名>.png`，或 `-o 指定文件` |
| CLI 批量 | `data/output/<原文件名>.png`，或 `--out-dir 指定目录` |

原图不动。目标目录里已有同名文件时不会覆盖，而是自动加序号：`示例-报告.png` → `示例-报告-1.png`
→ `示例-报告-2.png`（扩展名不变）。
输出路径如果正好等于原图（例如 `-o 原图.png`、或 `--out-dir` 指到输入目录），程序会拒绝写入并提示换目录。

TUI 里同一张图反复按 `r` 是覆盖**本次会话生成的**那个文件（不会每次留一份）；如果目标目录在会话开始前
就已经有同名文件，则会用 `-1`、`-2` 这样的新名字。
批量默认输出 PNG（无损，避免二次压缩）；需要 jpg 就单张用 `-o 名字.jpg`。

### 6.1 写盘日志

每真实写出一个图片文件（替换结果或 `--debug` 的 mask 图），都会往日志目录追加一条记录；
`--dry-run` 只预演不写盘，也就不记日志。

- 位置：仓库根 `logs/image-writes-YYYYMMDD.log`（按天分文件，一行一个 JSON，只追加）。
- 改位置：CLI 用 `--log-dir DIR`，或设环境变量 `IMG_P_LOG_DIR`（TUI 也认）。
- 一条记录包含：发生时间、渠道（cli/tui）、源文件名与字节数、目标文件名与字节数、
  每个替换处的旧文字→新文字（行内替换另带“命中的子串 + 它在整行里的位置”）、模式（整体/子串）、
  字体、字号、字距、颜色、对齐、匹配度，以及你显式设置过的样式选项。例如：

```json
{"time":"2024-05-01T12:30:15+08:00","channel":"cli","action":"替换文字并保存图片",
 "src_file":"示例-报告.png","src_size":48213,"dst_file":"示例-报告.png","dst_size":47980,
 "dst_sha256":"9f2c…","dst_width":1200,"dst_height":800,"replaced":1,
 "operations":[{"old":"年度报告2023","new":"年度报告2024","fragment":"2023","span":[4,8],
 "mode":"子串","rect":[64,58,362,39],
 "font":"NotoSansCJK-Regular","size":36,"tracking":0.0,"color":[30,30,30],
 "align":"center","iou":0.93}]}
```

`fragment` 是行内替换实际命中的原文子串，`span` 是它在该行里的字符区间 `[起, 止)`；
`old` 仍是整行原文、`new` 是写进图里的新文字（整行替换时 `fragment` 与 `span` 为 `null`）。
旧日志没有这两个字段，查询与读取照样正常（读到 `null`）。

日志写不进去（目录不可写等）只会在 stderr 提示一句，图片照常保存。

查日志不用手翻 JSON：

```bash
.venv/bin/./scripts/log-query.sh                    # 最近日志的汇总 + 明细
.venv/bin/./scripts/log-query.sh --src 报告          # 只看这个原图被换过什么
.venv/bin/./scripts/log-query.sh --date 20261110     # 只看某一天
.venv/bin/./scripts/log-query.sh --channel tui --json  # 渠道过滤 + 机器可读
```

坏行（被外部截断/手工改坏）会被跳过，不会让整份日志读不出来。

`--dry-run` 预演不写任何文件（包括 `--debug` 的 mask 图），所以也不会产生日志；
此时如果同时给了 `--debug`，程序会提示“已忽略”。

## 7. 命令行参数速查

| 参数 | 说明 |
| --- | --- |
| `input` | 图片文件，或图片目录（目录 = 批量） |
| `-o/--output` | 单图输出文件；批量时等价于输出目录 |
| `--out-dir` | 批量输出目录，默认 `data/output` |
| `--map OLD=NEW` | 替换对，可重复 |
| `--map-file` | JSON 映射表：`{"旧": "新"}` |
| `--area X,Y,W,H=新文字` | 手工框一块区域替换，仅单图 |
| `--list` | 只列出识别到的文字块 |
| `--dry-run` | 只报告不写文件（也不再跑擦除/绘制，大目录预演很快） |
| `--font` | 强制字体文件（`.ttf/.otf/.ttc`） |
| `--size` | 强制字号 |
| `--color` | 强制字色，`#FF0000` 或 `255,0,0` |
| `--tracking` | 强制字距（px，可负） |
| `--fit-width` | 调字距让新文字宽度贴合原宽度 |
| `--align` | `auto`/`left`/`center`/`right`，默认 auto |
| `--max-fonts` | 候选字体上限，默认 160 |
| `--min-score P` | OCR 置信度下限 0-1，低于它的块不参与匹配（默认 0=不过滤） |
| `--fuzzy P` | 模糊兜底阈值 0-1，默认 0.8（某个字都没直接命中时才用） |
| `-j/--workers 1\|auto\|N` | 批量并发档。默认 `1`（实测逐图并发更慢）；`auto`=核数一半且≤4；`N`=指定。也可用环境变量 `IMG_P_WORKERS`；`--dry-run` 恒为 1 |
| `--debug DIR` | 导出每处文字的二值 mask 便于排查 |
| `--log-dir DIR` | 写盘日志目录，默认 `logs/` |
| `--quality N` | JPEG/WEBP 输出质量 1-100，默认 95 |
| `--report FILE` | 把本次运行摘要（成功/失败/替换明细）写成 JSON |
| `--quiet` | 少打印 |

TUI 也接受同名的覆盖参数：`-o/--out-dir`、`-m/--map-file`、`-f/--font`、`--color`、`--align`、
`--size`、`--tracking`、`--max-fonts`、`--fit-width`、`--quality`、`--log-dir`。

## 8. 常见问题

### Q：测试红了怎么快速定位？（只跑那一条，不要重跑全量）
A：
```bash
.venv/bin/python -m src.python.tools.test_failures            # 列出失败用例 + 单跑命令
.venv/bin/python -m src.python.tools.test_failures --json     # 机器可读（给脚本用）
.venv/bin/python -m src.python.tools.test_order_dependent <节点ID>   # 单跑绿、一起跑红 → 找污染源
```
`test_failures` 读 `reports/junit.xml`，给出 pytest 节点 ID、失败类型/消息首行和可直接粘贴的复现命令；
`test_order_dependent` 会先确认"单跑确实通过"，再二分出最小的污染前缀，最后输出污染源文件与最小复现命令
（退出码 0=已定位，1=非顺序依赖，2=无法复现）。

### Q：`ModuleNotFoundError: No module named 'PIL'` / 提示「当前用的是系统解释器」。
A：改走项目虚拟环境——`./scripts/cli.sh`、`./scripts/tui.sh`、`./scripts/run-test.sh` 都会自动用
`.venv`（缺就自动建）；直接跑模块时用 `.venv/bin/python -m src.python.cli`。CLI/TUI/`check_all`
在检测到系统解释器时会先打一句提示（CI 环境不提示）。

### Q：替换后字体不像原图。
A：系统里没有那款字体。用 `--font 字体文件` 指定同族字体；或确认终端里 `fc-list | grep 字体名` 能查到。

### Q：中文显示成方块 / 报“找不到可用字体”。
A：系统缺中文字体，装一个（如 `fonts-noto-cjk`）或用 `--font` 指定 `.ttc/.ttf`。

### Q：提示「字体自动匹配不可靠」。
A：这一块的原文没被完整识别（多见于 `--area` 手工框），会退回默认字体。用 `--font` 指定字体，
或改用 `--map` 让 OCR 拿到完整整行文字。

### Q：我要改的字没被识别出来。
A：`./scripts/cli.sh 图.png --list` 看看实际识别结果；拿不到就用 `--area` 手工框：

```bash
./scripts/cli.sh data/x.png --area "120,300,420,60=全新的标题"
```

### Q：新文字比原文字长很多，挤在一起。
A：默认保持原字号，只调整对齐；想要贴合原宽度就加 `--fit-width`，或者用 `\n` 分行。

### Q：背景是照片/花纹，擦除后能看出痕迹。
A：这类区域建议先修图再替换；纯色、渐变背景通常无痕。

### Q：界面出现在手机上但显示「终端太小」，我的终端有那么小吗？
A：这个数字是终端自己上报的列×行（顶栏也会显示 `[宽x高]`），不是你猜的。
手机竖屏 + 大字号很容易只有 30 多列；有些 SSH 客户端不把窗口尺寸传给远端，也会报出偏小的值。
现在 32 列也能用：宽度 < 60 列会自动切到**单栏模式**（一次只显示一栏，`Tab` 在图片/文字之间切换），
只有小于 16 列或 8 行才显示占位提示。想看到完整双栏就把字号调小或横屏。

### Q：手机上用，动一下屏幕/转屏就退出了。
A：已经处理：`Esc` 只返回不退出（退出统一用 `q`），窗口尺寸变化（转屏、弹出键盘、SSH 客户端调整大小）
会重新排版而不是退出；窄于 60 列自动切单栏布局，小于 16 列才显示「终端太窄」提示并继续运行。
如果仍然退出，多半是终端把某个手势发成了 Ctrl-C 或断开了连接，可以换 Termux / JuiceSSH 这类支持
全屏 curses 的客户端，并把字号调小让窗口至少有 80×20。

### Q：TUI 按 `r` 好像没反应。
A：按下会立刻显示「正在替换，请稍等…」，结束后是「已保存 <路径>」。若提示「没有可替换的块」，
说明还没给任何块设置新文字（先 `Enter` 或 `i`）。同图重复替换很快，可以随便试。

### Q：TUI 提示「这行里找不到『xxx』」。
A：行内替换的“旧文字”必须在该行里真实存在（空格、全角半角都算），也可以改用 `Enter` 整行换。

### Q：写参数时打错了会怎样？
A：命令行会立刻给一句原因就退出（如 `颜色格式错误: zzz`、`字体文件不存在: /no/x.ttf`、
`--area 坐标错误: x,y,z`），不会跑到一半才失败；TUI 里改样式选项填错只会在底部提示，程序继续运行。

### Q：会覆盖原图吗？
A：不会。输出固定写到 `data/output/`（或你指定的目录），原图保持不变。

## 9. 自动测试

```bash
./scripts/run-test.sh              # 跑全部用例并生成测试报告
./scripts/run-test.sh --fast       # 只跑用例，不算覆盖率、不出 HTML
./scripts/run-test.sh -k 映射规则   # 其余参数原样透传给 pytest
```

报告产物在 `/test-reports/`（建不出来时退回 `./reports`）：

| 文件 | 内容 |
| --- | --- |
| `test-report.html` | 逐用例结果与失败详情 |
| `coverage/index.html` | 行覆盖明细 |
| `junit.xml` | CI 用的 JUnit 结果 |
| `summary.md` | 用例数、通过/失败、覆盖率汇总 |

测试过程中产生的临时文件（图片、日志、字节码、pytest 缓存）统一写 `/data/tmp`，不会和
`data/output`、`logs/` 里的真实产物混在一起；脚本跑完会清掉仓库里的 `__pycache__` / `.pytest_cache`。

也可以直接跑：`.venv/bin/python -m pytest src/test -q`（先
`.venv/bin/pip install -r requirements-dev.txt`）。当前基线：**138 个用例全绿，行覆盖约 77%**。

用例按场景分目录：

| 目录 | 覆盖 |
| --- | --- |
| `src/test/core/` | 匹配规则、渲染与字距、样式分析、擦除与绘制、图片读写、字体池与缓存、OCR 封装、错误契约 |
| `src/test/tui/` | 按键归一与导航、样式选项面板、全局映射面板、布局渲染（宽屏/窄屏/过窄）、替换与批量流程 |
| `src/test/cli/` | 参数解析与合并、单图流程（`--list`/dry-run/样式覆盖）、目录批量（命名/汇总/过滤） |
| `src/test/_support.py` | 公共设施：字体路径、合成图、OCR 桩、`FakeWin`、用例基类 |

## 10. 使用限制

- 手写体、艺术变形字、极粗描边字：需要 `--font` 指定同族字体。
- 竖排文字、旋转文字：按水平排版处理，不做旋转适配。
- 文字被遮挡、压在半透明色块上时，擦除与字体判断都可能不准。
- 一次替换是“重新生成”，不会保留你上次手动涂改的痕迹（因为总是从原图开始）。
